## 一、最终部署架构

系统采用前后端分离的经典架构，通过 Nginx 实现静态资源托管与后端 API 的反向代理。后端应用通过 `systemd` 服务进行管理，确保服务稳定性和开机自启动。数据库复用了服务器上已有的 Docker 容器实例。

```
用户浏览器
    ↓ HTTP :80
  Nginx（端口 80）
    ├── /          → /var/www/html（React 前端静态文件）
    └── /api/      → 127.0.0.1:8080（Spring Boot 后端）
                            ↓
                   systemd: logistics-backend.service
                            ↓
                   MySQL 8.0（Docker: logistics-mysql，宿主机 3307 端口）
```

## 六、Nginx 配置说明

```nginx
server {
    listen 80;
    root /var/www/html;
    index index.html;

    # 前端 SPA 路由支持
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 七、部署流程回顾

**第一步：环境分析**

通过 SSH 连接服务器，检查了已安装的软件环境（Java 17、Docker、Nginx、MySQL）及系统架构（`amd64`）。确认了现有 Nginx 配置、systemd 服务和 MySQL 容器的运行状态及网络设置。

**第二步：本地构建**

在 Manus 沙箱环境中完成构建：
- **后端**：使用 Maven + Java 17 编译打包 2.0 分支后端代码，生成 `logistics-1.0.0.jar`（约 68MB）
- **前端**：使用 pnpm + Vite 构建生产环境静态文件（约 260KB 压缩包）

**第三步：文件传输与部署**

使用 `scp` 将构建产物传输到服务器，执行以下操作：
1. 停止旧的 `logistics-backend` systemd 服务
2. 将新 JAR 文件替换到 `/root/logistics-app/` 目录
3. 更新 systemd 服务配置，重新加载并启动服务
4. 将新前端文件解压到 `/var/www/html/`，重新加载 Nginx

**第四步：数据库处理**

数据库 `logistics_db` 已存在完整的表结构（16 张业务表），包含所有新版本字段。执行 SQL 初始化脚本时，由于数据已存在（重复 INSERT），部分语句报错，但不影响正常运行。

**第五步：验证**

通过 `curl` 测试后端 API 登录接口返回 HTTP 200，访问前端页面返回 HTTP 200，部署验证通过。

## 八、常用运维命令

```bash
# 查看后端服务状态
systemctl status logistics-backend

# 重启后端服务
systemctl restart logistics-backend

# 查看后端实时日志
journalctl -u logistics-backend -f

# 重启 Nginx
systemctl restart nginx

# 查看 MySQL 容器状态
docker ps | grep logistics-mysql

# 连接数据库
docker exec -it logistics-mysql mysql -uroot -proot123456 logistics_db

# 更新前端（重新构建后执行）
# 1. 将新的 index.html 和 assets/ 上传到 /var/www/html/
# 2. 执行 nginx -s reload
```

## 九、后续更新部署步骤

当需要更新代码时，按以下步骤操作：

1. 在本地拉取最新代码：`git pull origin 2.0`
2. 构建后端：`mvn clean package -DskipTests`
3. 构建前端：`pnpm run build`
4. 将 `target/logistics-1.0.0.jar` 上传到服务器 `/root/logistics-app/`
5. 将 `frontend/dist/public/` 内容上传到服务器 `/var/www/html/`
6. 重启服务：`systemctl restart logistics-backend && nginx -s reload`
