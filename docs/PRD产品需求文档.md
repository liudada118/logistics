## 1. 产品概述

本系统是一套面向物流企业的运营管理平台，覆盖从货物受理、运输调度、签收管理到财务结算的完整业务链路。系统以蓝桥T9为业务参考标准，在保持核心业务逻辑一致的基础上，提供更现代化的用户体验。

**目标用户角色**：

| 角色 | 职责描述 |
|---|---|
| **系统管理员** | 管理用户、权限、基础数据配置 |
| **开单员** | 受理货物、录入运单信息 |
| **调度员** | 安排发货、分配车辆和司机 |
| **仓管员** | 管理发货库存、到货库存 |
| **司机** | 执行运输任务、更新运输状态 |
| **财务员** | 处理收款、核销、月结对账 |
| **客服** | 查询运单状态、处理异常 |

---

## 2. 整体业务流程

物流系统的核心业务流程分为四个阶段，形成完整的货物流转闭环：

```
[受理开单] → [运输调度] → [派送签收] → [财务结算]
     ↓              ↓             ↓             ↓
  生成运单      分单配载       到货入库       应收核销
  打印标签      车辆跟踪       客户提货       月结对账
  收取运费      到货确认       签收回单       请款审批
```

**运单完整状态流转**：

```
待调度 → 运输中 → 已到货 → 派送中 → 已签收
  ↓                              ↓
异常登记                       回单处理
  ↓
异常处理 → 恢复正常流程
```

| 字段 | 类型 | 必填 | 规则 |

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| 现付 | Float | ❌ | 开单时现金支付，默认0 |

| 字段 | 类型 | 必填 | 规则 |

#### 3.3.2 运单号生成规则

运单号格式：`YT` + `YYYYMMDD` + `4位流水号`

示例：`YT202603010001`

规则：每天从0001开始，当天最大支持9999票。流水号不足4位时左补0。

## 5. 模块三：财务中心

### 5.1 功能概述

财务中心负责处理所有与资金相关的业务，包括运费收取、代收货款核销、月结对账、请款审批等。

### 5.2 子模块说明

#### 5.2.1 财务做账

记录日常财务凭证，包括：
- **管理费用请款**：行政/管理类支出申请
- **业务支出请款**：运营业务类支出申请

| 字段 | 说明 |
|---|---|
| 请款类型 | 管理费用/业务支出 |
| 请款金额 | |
| 用途说明 | |
| 附件 | 发票/收据等 |
| 审批状态 | 待审批/已审批/已拒绝 |

#### 5.2.2 现金录入

记录现金收支流水。

| 字段 | 说明 |
|---|---|
| 收支类型 | 收入/支出 |
| 金额 | |
| 摘要 | 业务说明 |
| 关联运单 | 可关联具体运单 |
| 经手人 | |

#### 5.2.3 结款核销

将应收款项与实际收款进行核销匹配。

**核销规则**：
- 现付运单：开单时即产生应收，收款后核销
- 提付运单：到货后产生应收，收款后核销
- 月结运单：月末统一出账，对账后核销
- 货款扣运单：代收货款到账后，扣除运费核销

| 字段 | 说明 |
|---|---|
| 核销单号 | 系统自动生成 |
| 核销金额 | |
| 核销方式 | 现金/银行转账/微信/支付宝 |
| 核销时间 | |
| 关联运单 | 本次核销涉及的运单列表 |

#### 5.2.4 请款审批

对请款申请进行审核。

**审批流程**：提交申请 → 主管审批 → 财务审批 → 出纳付款

| 状态 | 说明 |
|---|---|
| 待审批 | 已提交，等待审批 |
| 审批中 | 部分审批通过 |
| 已审批 | 全部审批通过，等待付款 |
| 已付款 | 款项已支付 |
| 已拒绝 | 审批不通过 |

#### 5.2.5 月结对账

对月结客户进行月末统一对账。

**业务流程**：
1. 月末生成月结账单（汇总当月所有月结运单）
2. 发送账单给客户确认
3. 客户确认后付款
4. 收款后进行核销

| 字段 | 说明 |
|---|---|
| 账单周期 | 年月 |
| 客户 | 月结客户 |
| 运单数量 | 当月运单总数 |
| 应收金额 | 当月月结运费总额 |
| 已收金额 | 已核销金额 |
| 未收金额 | 应收 - 已收 |

#### 5.2.6 代收货款管理

管理代收货款（COD）的收取和转付。

**业务规则**：
- 收货人支付代收货款给司机/网点
- 网点将代收货款转付给发货方（扣除运费后）
- 如付款方式为"货款扣"，则从代收货款中直接扣除运费

| 字段 | 说明 |
|---|---|
| 代收金额 | 应向收货人收取的金额 |
| 实收金额 | 实际收取金额 |
| 转付金额 | 转付给发货方的金额 |
| 转付状态 | 待转付/已转付 |

## 10. 非功能性需求

### 10.1 性能要求

| 指标 | 要求 |
|---|---|
| 页面加载时间 | ≤ 2秒（首屏） |
| 列表查询响应 | ≤ 1秒（10000条以内） |
| 并发用户数 | ≥ 100 |
| 数据库查询 | 核心接口 ≤ 500ms |

### 10.2 安全要求

- 所有接口需要 JWT 认证
- 密码使用 BCrypt 加密存储
- 敏感操作（删除、审批）记录操作日志
- 支持 HTTPS

### 10.3 兼容性要求

- 支持 Chrome 90+、Edge 90+、Firefox 90+
- 支持 1366×768 及以上分辨率
- 移动端支持查看运单状态（响应式布局）

### 10.4 数据备份

- 每日自动备份数据库
- 备份保留 30 天
- 支持手动导出数据
